# Синхронизация контента

**Статус:** Todo  
**Контекст:** Нужно добавить триггеры после публикации и очистку кеша.

## Цель
- Гарантировать актуальность поискового индекса при изменениях данных в Strapi.

## Декомпозиция
1. Определить события Strapi, которые должны инициировать синхронизацию (create/update/delete/publish).
2. Реализовать lifecycle hooks или webhook-и, отправляющие данные в очередь/воркер индексации.
3. Настроить батчевое обновление для массовых изменений и полнотекстовой переиндексации.
4. Обеспечить согласованность с кэшем Redis и ISR: очистка после обновления индекса.
5. Реализовать механизм retry и dead-letter queue для неудачных синхронизаций.
6. Настроить наблюдаемость: логи, метрики количества обновлений и ошибок.
7. Подготовить тестовые сценарии: публикация, снятие с публикации, удаление сущностей.
8. Документировать процесс и конфигурацию, определить ответственных за поддержку.

## Контрольные точки
- Обновление записей в Strapi отражается в Meilisearch в пределах SLA.
- При сбое синхронизации присутствуют уведомления и инструкции по восстановлению.

## Риски и допущения
- Отсутствие очередей при высоком объёме изменений может перегрузить Meilisearch.
- Неправильные фильтры приведут к появлению приватных данных в поиске.
