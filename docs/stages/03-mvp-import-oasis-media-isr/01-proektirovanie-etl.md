# Проектирование ETL

**Статус:** Done  
**Контекст:** Процесс описан в документе по проектированию (батчи, ретраи, ISR).

## Цель
- Определить стратегию импорта данных из Oasis, их обогащение и доставку в Strapi/Meilisearch.

## Декомпозиция
1. Собрать требования к объёму данных, частоте обновлений и SLA.
2. Определить источник данных Oasis: эндпоинты, фильтры, механизмы инкрементального обновления.
3. Спроектировать схему staging-хранилища и ориентацию на idempotent обработку.
4. Описать пайплайн трансформаций: нормализация атрибутов, маппинг категорий, локализации.
5. Спланировать обработку медиа: загрузка, дедупликация, связывание с товарами.
6. Определить механизм триггеров для переиндексации и инвалидации кэшей.
7. Зафиксировать механизмы ретраев, мониторинга и точек падения.
8. Оформить документацию с диаграммой потоков и списком ответственных.

## Результаты
- Есть детализированная схема ETL, служащая входом для реализации импортов в следующих задачах.

## Риски и допущения
- Изменения на стороне Oasis могут нарушить ранее согласованную схему.
- Недостаток логирования на этапе исполнения усложнит расследование сбоев.
