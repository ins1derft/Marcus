# ISR и переиндексация

**Статус:** Todo  
**Контекст:** Требуется подключить on-demand revalidate и вызовы Meilisearch после обновления данных.

## Цель
- Обеспечить актуализацию фронтенда и поискового индекса после импорта данных.

## Декомпозиция
1. Проанализировать точки, где изменения в каталоге должны инициировать revalidate (товары, категории, коллекции).
2. Настроить Strapi webhooks или cron-хуки, вызывающие Next.js API routes для `revalidate`.
3. Определить стратегии ISR: TTL страниц, fallback mode, обработка ошибок revalidate.
4. Реализовать сервис переиндексации Meilisearch: обновление документов, сброс фасетов, очистка устаревших записей.
5. Настроить батчевую переиндексацию для массовых изменений (полный импорт).
6. Обеспечить наблюдаемость: логировать вызовы revalidate и индексатора, метрики по времени ответа.
7. Написать тесты e2e/интеграционные на сценарии обновления товара и появления новых категорий.
8. Документировать процесс, указать как запускать ручную переиндексацию и проверять статус.

## Контрольные точки
- Страницы обновляются не позднее SLA после изменений в Strapi.
- Поиск отражает новые и обновлённые товары без ручного вмешательства.

## Риски и допущения
- Частые revalidate могут перегрузить Next.js и Meilisearch без очередей.
- Ошибки в webhookах приведут к расхождению данных между CMS и фронтендом.
