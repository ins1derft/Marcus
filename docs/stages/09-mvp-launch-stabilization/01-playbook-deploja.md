# Playbook деплоя

**Статус:** Done  
**Контекст:** README фиксирует ручной деплой `docker compose build/up`.

## Цель
- Описать чёткий набор шагов для развёртывания продукта в продакшен.

## Декомпозиция
1. Зафиксировать требования к окружению (версии Docker, доступы, переменные окружения).
2. Описать последовательность подготовки: обновление репозитория, сборка образов, миграции.
3. Добавить процедуры проверки перед деплоем (health-check, smoke tests).
4. Описать команды запуска и мониторинга (`docker compose build/up`, логирование, статус).
5. Зафиксировать процедуру отката и восстановления после неудачного деплоя.
6. Определить роли/ответственность и каналы коммуникации во время релиза.
7. Документировать check-list постдеплойных проверок.

## Результаты
- Команда следует playbook без зависимости от устной передачи знаний.

## Риски и допущения
- Изменения инфраструктуры требуют актуализации playbook.
- Отсутствие автоматизации повышает риск человеческого фактора.
