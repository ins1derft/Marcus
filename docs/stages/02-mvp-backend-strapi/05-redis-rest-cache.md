# Redis REST cache

**Статус:** Done  
**Контекст:** Плагин `@strapi-community/plugin-rest-cache` с Redis включён в конфигурацию Strapi.

## Цель
- Снизить нагрузку на Strapi и ускорить ответы REST API за счёт кэширования.

## Декомпозиция
1. Выбрать и настроить Redis инстанс (docker сервис, managed, параметры persistence).
2. Установить плагин rest-cache, определить стратегии инвалидации для коллекций.
3. Настроить ключи кэша, TTL и исключения (админские endpoints, приватные данные).
4. Подключить middleware для автоматической очистки кэша при изменении сущностей.
5. Реализовать ручные invalidation endpoints при сложных зависимостях.
6. Настроить мониторинг Redis (memory, hit ratio, latency) и алёрты.
7. Провести нагрузочные тесты, сравнить время ответов до/после.
8. Обновить документацию, донести до команды правила работы с кэшем.

## Результаты
- REST API Strapi быстрее отвечает на публичные запросы, нагрузка стабилизирована.

## Риски и допущения
- Неправильная инвалидация приведёт к устаревшим данным на фронтенде.
- Перегруженный Redis может стать single point of failure без кластеризации.
