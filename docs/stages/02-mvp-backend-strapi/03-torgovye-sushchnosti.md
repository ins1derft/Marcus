# Торговые сущности

**Статус:** Done  
**Контекст:** Реализованы Order, Quote Request, PrintingMethod, Portfolio и другие сущности.

## Цель
- Поддержать ключевые торговые процессы (заказы, расчёт нанесения, портфолио) в CMS.

## Декомпозиция
1. Выявить бизнес-процессы и атрибуты для заказов, запросов на расчёт, методов нанесения.
2. Создать соответствующие коллекции и компоненты, определить связи между сущностями.
3. Настроить workflow статусов и кастомные поля (MOQ, цены, сроки производства).
4. Реализовать бизнес-валидации и lifecycle hooks (auto slug, расчёт derived полей).
5. Подготовить seed/скрипты для тестовых данных и демо-каталога.
6. Обновить API endpoints, передать фронтенду контракты и примеры ответов.
7. Зафиксировать процессы обновления данных: кто и как поддерживает актуальность.
8. Провести ревью схемы с product-owner и командой заказчика.

## Результаты
- CMS отражает торговые процессы и служит источником данных для фронтенда и интеграций.

## Риски и допущения
- Смена бизнес-логики потребует мануальных миграций и обновления frontend-клиентов.
- Недостаточный контроль ролей может раскрыть конфиденциальные поля внешним пользователям.
